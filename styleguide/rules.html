규칙 색인

이 디자인 시스템이 지키는 규칙을 번호로 모은 장입니다. 디자인 QA에서는 규칙을 번호로 부릅니다. 예를 들어 오답 칸에 분홍 면이 보이면 RM-SURF-02 위반입니다. 번호를 누르면 이 카드로 옵니다.

규칙의 정본은 이 장입니다. tools/rules-build.py가 카드를 읽어 styleguide/data/rules.json과 CLAUDE.md 색인을 만들고, 다른 파일에 인용된 번호가 정본과 맞는지 대조합니다.

읽는 법 번호 · 카드 · 검사

번호는 RM-영역-번호입니다. 한 번 붙인 번호는 바꾸지 않습니다. 규칙을 폐기해도 카드를 남겨 같은 번호를 다른 뜻으로 쓰지 않습니다.

카드는 제목(지킬 것) · 어떻게 · 검사 · 예외 순서이고, 근거는 접혀 있습니다. 검사 딱지가 기계면 도구가 숫자로 잡고, 눈이면 화면을 보고 판단합니다.

색은 tokens.css의 변수로만 쓴다

화면 CSS·JS와 HTML style=""에 hex·rgb()를 직접 쓰지 않는다. 색값은 styles/tokens.css 한 곳에만 있다.

검사

예외

반투명은 알파 램프 또는 「토큰을 N% 섞기」 두 문법만

흰·검 반투명은 --white-a10·--black-a30 같은 알파 램프로 쓴다. 색이 섞인 반투명은 color-mix(in srgb, var(--<토큰>) N%, transparent)로 쓴다. 섞는 색도 팔레트가 아니라 역할 · 부품 토큰이다(그림자는 --shade*, 계열 빛은 --th-*, RM-COL-05). 즉흥 rgba()를 만들지 않는다.

화면은 팔레트를 직접 부르지 않는다 — 2단 역할 · 부품 토큰으로 받는다

화면 CSS · JS · HTML은 --blue-500·--n-800 같은 1단 팔레트를 var()로 부르지 않는다. 먼저 같은 값 · 같은 뜻의 2단 역할(--surface-*·--text*·--divider*·--ok-*)과 계열 슬롯(--th-*)을 찾는다. 뜻이 없으면 tokens.css의 부품 토큰에서 이름을 받는다. 고정 다크 --hw-*, 고정 라이트 --paper-*, 그늘 --shade*, 화면군 --util-*·--exam-*·--assign-*가 있다. 새 이름이 필요하면 tokens.css에 만들고 화면은 그 이름만 쓴다.

잡은 것: 여러 줄 규칙을 한 줄만 지워 과제 화면이 백지가 된 것, 잘린 출력을 보고 옮겨 적어 다섯 화면의 라벨이 12px에서 13px로 커진 것, 기본형과 변형 중 변형만 옮겨져 훈련 결과표의 이름 칸이 가운데로 몰린 것. 셋 다 코드만 봐서는 보이지 않았다.

못 잡는 것: 눌러야 뜨는 것(토스트·모달), 다른 규칙에 가려진 것(그림 경로 404), 마우스 커서 모양, 화면이 쓰지 않는 테마에서만 생기는 차이. 2026-10-14 외부 검수에서 서술형 주어진 답 칸의 커서와 결과 계기판의 라이트 글자색이 이렇게 빠졌다. 이런 것은 이전 커밋과 계산 스타일을 대조해서 확인한다.

개발자 파일 스크립트가 만든다

아래 세 파일은 스크립트가 만듭니다. 개발자와 개발자의 AI가 그대로 읽을 수 있는 형식입니다. 고칠 일이 있으면 이 파일이 아니라 원본(토큰 · 이 장 · 화면)을 고치고 다시 만듭니다.

파일원본 → 만드는 도구무엇
styleguide/data/tokens.jsonstyles/tokens.css → tools/tokens-build.py 디자인 토큰 표준 형식(W3C DTCG). 역할 토큰과 에셋 연동색마다 라이트·다크 값, 계열마다 값이 갈리면 계열 7벌의 값, 원본 팔레트 이름을 싣는다.
styleguide/data/rules.json이 장 → tools/rules-build.py 규칙 카드 전부. 번호 · 지킬 것 · 근거 · 검사 · 예외.
