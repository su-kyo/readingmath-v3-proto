셸

화면을 감싸는 것들 — 상단 GNB와 서랍, 학습 헤더, 하단 콘솔바, 그 위에 뜨는 보조 모니터와 키패드, 그리고 화면 전체를 덮는 연습장. 이것들이 계열을 갈아입는 방식이 이 프로젝트의 뼈대입니다: 변형 클래스를 만들지 않고 data-section이 토큰만 교체합니다.

먼저 — 왜 우주선인가 모달이 아니라 「사물」이다

이 서비스의 화면은 우주선 조종석입니다. 그래서 셸은 웹 UI 관습이 아니라 하드웨어의 규칙을 따릅니다 — 아래에서 뜨는 알림 대신 위에서 내려오는 보조 모니터, 입력 필드 대신 트레이에 놓인 계산기, 툴바 대신 물리 버튼이 박힌 콘솔.

하드웨어는 테마를 안 따릅니다. 콘솔바와 키패드는 라이트·다크에서 같은 모습이에요. 우주선의 물건은 조명이 바뀐다고 색이 변하지 않으니까요. 바뀌는 것은 화면(패널) 안쪽입니다.

상단 GNB gnb.css · 항상 다크 (시험대비만 라이트 스킨)

모드 탭

.gnb · .gnb__mode.m-basic/m-free/m-exam/m-assign · .is-active gnb.css

활성 탭이 정체성 칠면입니다 — 각 모드의 450 스텝으로 칠하고 흰 굵은 라벨 19px w700을 얹습니다(3:1 · 다크 GNB와 면 대비 6.3). 600으로 낮췄더니 「칙칙하다」는 판정이 나와 폐기했어요. GNB는 테마 토글이 없습니다 — 늘 다크라 액자도 하나입니다. 과제 센터의 빨간 점은 안 읽은 과제가 있다는 뜻이고, 활성일 때는 흰 점으로 바뀝니다.

우측 서랍

.rmd · --rmd-face/raised/ink/line/fill scripts/gnb-drawer.js

서랍은 스타일을 JS 안에서 만들어 넣습니다 — 10화면이 함께 쓰는데 CSS 파일이 없어요. Phase 10-①에서 그 안의 색 36개를 토큰으로 바꿨습니다. 서랍은 항상 다크입니다: 서랍이 달린 GNB가 애초에 다크라 어두운 서랍이 어두운 GNB에서 미끄러져 나오는 것이 맞아요. 그래서 테마로 뒤집히는 --surface-*가 아니라 뒤집히지 않는 램프 --n-*를 직접 참조합니다.

서랍은 한때 v1.6 팔레트 이전에서 멈춰 있었습니다. CTA가 옛 주황(#FF7F00)이라 다른 화면의 --primary와 달랐고, 학기 탭은 흰 글자 대비가 4.1로 미달이었어요. 눈에 잘 안 띄는 종류의 어긋남이라 오래 남아 있었습니다 — 스타일이 CSS 밖(JS 문자열)에 있으면 이런 일이 생깁니다. Phase 10-①에서 색을, 마감 회차에서 반투명 색과 토스트 상태 이름까지 토큰·규칙에 맞췄습니다. 로고 5색만 브랜드 마크라 예외로 둡니다(「패턴 › 남긴 예외」).

학습 화면 셸 learn-shell.css · 19화면 공유

배경 → 헤더 → 콘텐츠 패널 → 콘솔바 순으로 쌓입니다. 다섯 화면이 이 셸 전체를 각자 복사해 갖고 있었고, Phase 10-③에서 링크로 바꿨어요.

학습 헤더

.lheader · .breadcrumb · .lheader__timer · .nav-ico · .theme-toggle learn-shell.css

면색이 --th-static입니다 — 계열의 가장 깊은 톤이고 라이트·다크에서 값이 안 바뀝니다(과목 정체성 앵커). 그래서 액자 둘의 헤더 색이 같아요. 경로가 길면 마지막 조각만 말줄임합니다(.crumb--clip) — 앞쪽 학년·단원이 먼저 잘리면 어디 있는지 알 수 없으니까요. 타이머는 .is-paused에서 흐려지고 앞에 정지 표시가 붙습니다.

하단 콘솔바

.bar · .bar__deco--l/r · .bar__mid · .bar__tray · .bar__group learn-shell.css

양끝 262px는 계열별 일러스트(SVG)이고 가운데만 늘어납니다. 트레이·립 면색은 에셋 연동색이라 그림의 실제 면색과 맞춰 박제돼 있어요 (--asset-bar-rim · --asset-bar-tray). 계열을 바꾸면 색과 그림이 함께 따라옵니다 — 아래 넷은 마크업이 완전히 같고 data-section만 다릅니다. 콘솔바는 라이트·다크가 같은 모습이라(우주선의 하드웨어) 액자를 하나만 세웁니다.

콘솔바 — 계열 넷

data-section="concept | type | essay | assign"

같은 마크업, 다른 data-section. 변형 클래스가 없습니다. 단 하나 예외가 좌우 일러스트예요 — 아래 주의 참고.

화면이 900px보다 좁아지면 좌우 일러스트가 사라집니다 (.bar__deco { display: none }). 대신 가운데 립이 22px 라운드를 얻어 혼자서도 콘솔로 보이게 마감돼요. 좁은 화면에서 262px짜리 장식 둘을 붙들고 있으면 정작 버튼 자리가 없어집니다. 680px에서는 경로의 중간 조각이, 520px에서는 도구 버튼의 글자가 빠집니다.
콘솔바에서 토큰이 아닌 곳은 좌우 일러스트 하나뿐입니다. 면색은 data-section이 정하는데, 그림은 각 화면 마크업의 <img src>가 고릅니다(console-right.svg · console-type-right.svg · console-essay-* · console-task-*). 이름도 좌우가 뒤바뀌어 있습니다 — 왼쪽 자리에 -right가 들어가요. 계열을 늘리면 이 8개 파일과 화면 마크업을 함께 챙겨야 합니다.

콘텐츠 패널 — 변형 둘

.content · .content--frame learn-shell.css

학습 패널은 8px 베젤 · 40px 라운드, 과제·시험 프레임은 6px 베젤 · 34px 라운드입니다. 비슷해 보이지만 Phase 7에서 따로 정한 규격이라 합치지 않고 변형으로 나눴습니다. 다크에서 학습 패널은 어두워지지만 프레임 변형은 화면이 --content로 직접 정합니다.

보조 모니터 monitor.css · 화면 위에 뜨는 모든 것의 한 벌

요약 · 영상 · 확대 · 끊어읽기 · 보고서 미리보기 · 답안표가 전부 이 틀을 씁니다. 웹 모달이 아니라 위에서 내려오는 보조 모니터예요 — 마운트 암 · 베젤 · 상태등 · 물리 버튼. 안의 내용은 화면 것을 그대로 넣습니다. 틀만 공용입니다.

보조 모니터

.monitor > __rig > __frame > (__hd · __screen · __chin) · .is-open monitor.css

크기는 페이지가 --mon-w 하나로 정합니다. 변형은 둘뿐이에요 — --side(오른쪽 도킹 · 답안표)와 --lock(닫기 없음 · 끊어읽기처럼 흐름을 강제할 때). 하드웨어는 전 계열 공통 네이비이고 계열 색은 상태등에만 들어갑니다.

키패드 keypad.css + keypad.js · 마크업까지 한 벌

키 구성은 한 벌로 고정입니다 — 7~0 · ⌫ · C · − · . · 확인. 마크업은 RMKeypad.html()이 만들고 값 편집은 RMKeypad.apply()가 합니다. 「확인」이 무엇을 하는지는 화면이 정합니다 — 개념·유형은 닫기, 서술형은 채점, 과제 좌측은 다음 문제, 답안표는 접기, 시험은 제출.

숫자 키패드

.keypad · __display · __grid · __key · --fn · --ok keypad.css · keypad.js

계산기는 우주선의 물건이라 라이트·다크에서 같은 모습입니다. 아래 액자 둘을 견줘 보세요 — 트레이와 키가 똑같습니다. 계열 차이는 --th-* 슬롯 교체만으로 나요(트레이 틴트 · LCD 글자색). 물리 키보드도 됩니다: keypad-input.js가 누른 키에 해당하는 화면 버튼을 대신 클릭합니다 — 입력 로직을 두 벌 만들지 않기 위해서예요.

같은 키패드, 계열만 유형

data-section="type"

마크업도 CSS도 위와 완전히 같습니다. 액자의 data-section만 type으로 바꿨어요 — 트레이 틴트와 LCD 글자색이 틸로 따라옵니다.

data-section은 :root에만 걸립니다 — 한 화면 안에서 계열을 섞을 수 없어요. 계열은 화면 단위로 정해지는 값입니다. 그래서 위 두 견본이 한 액자가 아니라 두 액자입니다.

연습장 scratchpad.js · 22화면 · 이 문서에서는 못 세운다

한 줄만 부르면 그 화면의 「연습장」 버튼에 알아서 붙습니다. 화면 위를 덮는 투명 캔버스에 바로 필기하고, 딤은 필기 뒤에 깔립니다 — 그려 놓은 선이 딤에 묻히면 안 되니까요. 문제 영역과 콘솔바는 딤에서 빠집니다.

도구 바는 그 화면의 .bar를 복제해 네이비로 다시 칠한 것입니다. 그래서 트레이 형태와 좌우 일러스트가 자동으로 따라와요 — 콘솔바 구조를 바꾸면 연습장을 반드시 함께 확인합니다. 검수는 주소 끝에 ?scratch=1.
