셸

화면을 감싸는 틀입니다. 상단 GNB와 서랍, 학습 헤더, 하단 콘솔바, 그 위에 뜨는 보조 모니터와 키패드, 화면 전체를 덮는 연습장.

셸은 우주선 조종석의 하드웨어처럼 그립니다. 알림 대신 위에서 내려오는 보조 모니터, 입력 필드 대신 트레이에 놓인 계산기, 툴바 대신 물리 버튼이 박힌 콘솔을 씁니다. 하드웨어(콘솔바 · 키패드 · GNB · 서랍)는 테마를 따라가지 않고, 바뀌는 것은 패널 안쪽입니다. 계열은 변형 클래스 없이 data-section이 토큰만 바꿔서 입힙니다.

모드 탭

.gnb · .gnb__mode.m-basic/m-free/m-exam/m-assign · .is-active gnb.css

활성 탭이 정체성 칠면입니다. 모드마다 450 스텝으로 칠하고 흰 라벨 19px w700을 얹습니다(3:1, 다크 GNB와 면 대비 6.3). GNB에는 테마 토글이 없고 늘 다크라서 견본도 하나입니다. 과제 센터의 빨간 점은 안 읽은 과제가 있다는 뜻이고, 탭이 활성이면 흰 점으로 바뀝니다.

근거

활성 탭을 600으로 낮춰 봤지만 칙칙하다는 판정이 나와 450으로 되돌렸다.

우측 서랍

.rmd · --rmd-face/raised/ink/line/fill scripts/gnb-drawer.js

서랍 스타일은 styles/gnb.css 끝에 있습니다. 서랍을 쓰는 10화면이 모두 이 파일을 부릅니다. 서랍은 항상 다크입니다. 서랍이 달린 GNB가 다크라서, 어두운 GNB에서 어두운 서랍이 나오는 것이 맞습니다. 그래서 테마를 따라 뒤집히는 --surface-*가 아니라 뒤집히지 않는 램프 --n-*를 직접 씁니다(RM-PART-03). 로고 5색은 브랜드 마크라 토큰 검사에서 뺍니다(패턴 › 남긴 예외).

근거

서랍 CSS는 스크립트 안의 문자열(51줄)이라 검사 도구가 보지 못했다. 그래서 v1.6 팔레트 이전 상태로 오래 남아 있었다. CTA가 옛 주황(#FF7F00)이라 다른 화면의 --primary와 달랐고, 학기 탭의 흰 글자 대비는 4.1로 미달이었다.

Phase 10-①에서 색을, 2026-10-12에 반투명 색과 토스트 상태 이름을 맞췄고, 2026-10-14에 CSS 파일로 옮겼다(RM-JS-01).

학습 헤더

.lheader · .breadcrumb · .lheader__timer · __time · __limit · .is-over · .is-paused · .nav-ico · .theme-toggle learn-shell.css

면색은 --th-static입니다. 계열의 진한 톤이고 라이트·다크에서 값이 같습니다. 그래서 두 견본의 헤더 색이 같습니다. 경로가 길면 마지막 조각만 말줄임합니다(.crumb--clip). 앞쪽 학년·단원이 먼저 잘리면 현재 위치를 알 수 없기 때문입니다. 타이머(유형 · 서술형)는 「진행 시간 / 제한 시간」입니다. 제한 시간은 흰색 80% · 한 단계 작은 글자입니다(60%는 틸 칩에서 4.37로 작은 글자 기준 4.5에 못 미친다). 넘으면(.is-over) 진행 시간이 밝은 빨강(--no-on-dark)이 되고 칩에 2px 빨간 테두리(--no-solid)가 둘리며, 숫자는 계속 올라갑니다. 분은 60을 넘어도 분으로 셉니다(62:10 / 60:00). 해설 · 결과 화면은 .is-paused로 흐려지고 앞에 정지 표시가 붙습니다. 넘은 채 멈췄으면 빨강도 그대로 남습니다. 세는 동작과 넘었는지 판정은 scripts/learn-timer.js가 하고, 제한 시간은 .lheader__limit의 글자가 정본입니다.

근거

2026-10-15 전에는 진행 시간만 보였고 제한을 넘었는지 알 수 없었다. 결과 화면의 「시간 초과 감점」은 앰버였는데, 타이머와 같은 빨강으로 맞췄다(.chip--over). 넘었을 때의 표현은 칩 전체 빨강 · 숫자만 빨강 · 테두리와 점 세 안에서 「숫자 빨강 + 테두리」로 정했다.

세는 코드는 화면 7곳에 복사돼 있었고, 서술형 해설 2장은 정지 이름이 달라(--pause) 정지 표시가 붙지 않았다. 둘 다 이때 하나로 모았다.

하단 콘솔바

.bar · .bar__deco--l/r · .bar__mid · .bar__tray · .bar__group learn-shell.css

양끝 262px는 계열별 일러스트(SVG)이고 가운데만 늘어납니다. 트레이와 립의 면색은 그림의 실제 면색에 맞춘 에셋 연동색입니다(--asset-bar-rim · --asset-bar-tray). 계열을 바꾸면 색과 그림이 함께 바뀝니다. 아래 넷은 마크업이 같고 data-section만 다릅니다. 콘솔바는 라이트·다크에서 같은 모습이라 견본을 하나만 세웁니다.

콘솔바 안내

.guide · .guide__lamp · .is-ok · .is-no learn-shell.css · scripts/learn-guide.js

오른쪽 CTA 바로 왼쪽에 놓는 한 줄 안내입니다. 버튼이 왜 꺼져 있는지, 다음에 무엇을 할지를 말합니다. 글자는 상태와 상관없이 하나(--guide-ink)이고, 상태는 램프 색으로만 말합니다. 위부터 기본 · 정답 · 오답입니다. 문장은 화면 엔진이 RMGuide.set(문장, 'ok' | 'no')로 넣고, 빈 문장이면 숨깁니다. 18em을 넘는 문장은 두 줄로 접힙니다. 규칙은 RM-PART-07입니다.

같은 마크업에 data-section만 다릅니다. 변형 클래스는 없습니다. 예외는 좌우 일러스트 하나입니다(아래).

좁은 화면: 900px보다 좁으면 좌우 일러스트가 사라지고(.bar__deco { display: none }), 가운데 립이 22px 라운드를 얻어 혼자서도 콘솔로 보입니다. 262px짜리 장식 둘이 남으면 버튼 자리가 없어지기 때문입니다. 680px에서는 경로의 중간 조각이, 520px에서는 도구 버튼의 글자가 빠집니다.

콘솔바에서 토큰으로 바뀌지 않는 것은 좌우 일러스트 하나입니다. 면색은 data-section이 정하지만, 그림은 각 화면 마크업의 <img src>가 고릅니다 (console-right.svg · console-type-right.svg · console-essay-* · console-task-*). 파일 이름의 좌우가 뒤바뀌어 있어서 왼쪽 자리에 -right가 들어갑니다. 계열을 늘리면 이 8개 파일과 화면 마크업을 함께 챙깁니다.

콘텐츠 패널 — 변형 둘

.content · .content--frame learn-shell.css

학습 패널은 8px 베젤에 40px 라운드, 과제·시험 프레임은 6px 베젤에 34px 라운드입니다. 따로 정한 규격이라 합치지 않고 변형으로 둡니다. 다크에서 학습 패널은 어두워지고, 프레임 변형의 면은 화면이 --content로 직접 정합니다.

보조 모니터 monitor.css · 화면 위에 뜨는 것 전부

요약, 영상, 확대, 끊어읽기, 보고서 미리보기, 답안표가 모두 이 틀을 씁니다. 웹 모달이 아니라 위에서 내려오는 보조 모니터입니다(마운트 암 · 베젤 · 상태등 · 물리 버튼). 틀만 공용이고 안의 내용은 화면 것을 그대로 넣습니다(RM-PART-02).

보조 모니터

.monitor > __rig > __frame > (__hd · __screen · __chin) · .is-open monitor.css

크기는 페이지가 --mon-w 하나로 정합니다. 변형은 --side(오른쪽 도킹, 답안표)와 --lock(닫기 없음, 끊어읽기처럼 흐름을 강제할 때) 둘뿐입니다. 하드웨어는 모든 계열이 같은 네이비이고, 계열 색은 상태등에만 들어갑니다.

키패드 keypad.css + keypad.js · 마크업까지 한 벌 · 테마와 무관

키 구성은 한 벌로 고정입니다(7~0 · ⌫ · C · − · . · 확인). 마크업은 RMKeypad.html()이 만들고, 값 편집은 RMKeypad.apply()가 합니다. 「확인」이 하는 일은 화면이 정합니다. 개념·유형은 닫기, 서술형은 채점, 과제 좌측은 다음 문제, 답안표는 접기, 시험은 제출입니다.

숫자 키패드

.keypad · __display · __grid · __key · --fn · --ok keypad.css · keypad.js

계산기는 라이트·다크에서 같은 모습입니다(RM-PART-03). 두 견본의 트레이와 키가 같습니다. 계열 차이는 --th-* 슬롯만으로 납니다(트레이 틴트 · LCD 글자색). 물리 키보드도 됩니다. keypad-input.js가 누른 키에 해당하는 화면 버튼을 대신 클릭하므로, 입력 로직은 한 벌입니다.

같은 키패드, 계열만 유형

data-section="type"

마크업과 CSS가 위와 같고, 견본의 data-section만 type입니다. 트레이 틴트와 LCD 글자색이 틸로 바뀝니다.

data-section은 :root에만 걸리므로 한 화면 안에서 계열을 섞을 수 없습니다. 그래서 위 두 견본도 따로 세웠습니다.

연습장 scratchpad.js + scratchpad.css · 22화면 · 이 장에서는 견본을 세우지 못한다

스크립트와 CSS를 부르면 그 화면의 「연습장」 버튼에 자동으로 붙습니다. CSS는 화면 CSS 바로 뒤에 부릅니다. 화면 위를 덮는 투명 캔버스에 바로 필기하고, 딤은 필기 아래에 깔립니다. 문제 영역과 콘솔바는 딤에서 빠집니다. 검수할 때는 주소 끝에 ?scratch=1을 붙입니다.

근거

딤이 필기 위에 있으면 그려 놓은 선이 딤에 묻힌다.

스크립트가 CSS 40줄을 <style>로 넣던 것을 2026-10-14에 파일로 옮겼다(RM-JS-01). 2026-10-15까지는 복제한 바를 네이비로 다시 칠했다. 원래 콘솔바와 같은 모습이 낫다는 판단으로 걷었다.

도구 바는 그 화면의 .bar를 그대로 복제한 것이다. 모양 · 색 · 좌우 일러스트가 원래 콘솔바와 같고 트레이 안 버튼만 연습장 도구로 바뀌므로, 콘솔바 구조를 바꾸면 연습장도 함께 확인한다.
