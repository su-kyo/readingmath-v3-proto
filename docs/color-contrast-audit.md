# 색 대비 감사 · 적용 완료 (2026-08-17)

전 화면의 글자·배경 대비를 WCAG AA 기준(일반 4.5:1, 큰 글자 3:1)으로 재고,
미달한 곳을 전부 고쳤습니다.

## 결과

| | 작업 전 | 작업 후 |
| --- | --- | --- |
| 미달 조합 | 27종 · 74곳 | **0** |
| 화면에 색을 직접 쓴 곳(hex) | 76곳 | **0** |

측정 대상은 서비스 화면 36장입니다. `styleguide.html`의 팔레트 견본 칩
(색 위에 색 이름을 적은 것)은 견본의 성격상 제외했고, 대신 라벨이 어떤 칩 위에서도
읽히도록 고쳤습니다.

## 원인은 팔레트가 아니라 "단계 선택"이었습니다

색 자체가 나빴던 게 아니라, **역할에 맞지 않는 단계를 골라 쓴 것**이 원인이었습니다.
같은 실수가 화면마다 반복돼 74곳이 됐습니다. 네 가지 유형입니다.

**① 흰 글자를 500단계 위에 얹음** — 가장 많았습니다. 활성 탭, 솔리드 버튼, 배지.
500단계는 흰 글자와 3.7~4.4로 아깝게 미달합니다.

**② 밝은 배경 위 글자에 500단계** — 흰 카드 위 강조 텍스트. 4.0~4.5로 미달.

**③ 다크 배경 위 글자에 600·700단계** — 어두운 색을 어두운 배경에. 2.0~2.9로 크게 미달.

**④ 보조 텍스트의 테마별 배치가 뒤바뀜** — 라이트에 너무 흐린 값(n-300, 2.19),
다크에 너무 진한 값(n-400, 3.43)이 들어가 있었습니다. 서로 바꿔야 맞습니다.

## 고친 방법

### 토큰 층에서 (전 화면에 파급)

가장 심각했던 주 CTA와 GNB 모드색은 토큰 하나로 전 화면이 해결됐습니다.

| 토큰 | 전 | 후 | 대비 |
| --- | --- | --- | --- |
| `--primary` (주 CTA) | orange-400 | **orange-450** `#B75301` | 2.51 → **4.94** |
| `--mode-basic` | blue-500 | blue-600 | 4.08 → **6.71** |
| `--mode-free` | `#58CC02` | green-600 | 2.09 → **6.20** |
| `--mode-exam` | violet-500 | violet-600 | 4.38 → **7.25** |
| `--mode-assign` | orange-400 | orange-600 | 2.51 → **6.91** |
| `--text-meta` (다크) | n-400 | **n-350** `#7285A6` | 3.43 → **4.91** |

`--orange-450`과 `--n-350`은 이번에 새로 만든 단계입니다. 기존 램프의 400은 너무 밝고
500은 여전히 미달이라, 그 사이가 필요했습니다.

### 새 슬롯 — 같은 실수가 반복되지 않도록

`--th-solid`를 섹션마다 추가했습니다. **흰 글자가 올라가는 칠면**(활성 탭·솔리드 버튼·배지)은
반드시 이 슬롯을 씁니다. 이름에 역할이 박혀 있어서 잘못 고르기 어렵습니다.

```
--th-accent       500 · 테두리·진행바·강조선 (글자 받침으로 쓰지 않는다)
--th-solid        600 · 흰 글자가 올라가는 칠면        ← 새로 만듦
--th-ink-accent   600 · 밝은 배경 위 글자
--th-accent-hi    300 · 다크 배경 위 글자
```

호환 별칭 `--danger` `--info` `--success` `--warning`도 손봤습니다. 이 별칭들은 대개
다크 표면 위 글자로 쓰이는데 solid(500)를 가리켜 미달이었습니다. on-dark(300)로 바꿨습니다.

## 화면의 직접 색 지정 76곳 → 0

조사해 보니 이건 "즉흥 색"이 아니라 **이름이 없던 의도적 예외**였습니다.
색을 바꾸면 안 되는 것들이라, 값은 그대로 두고 토큰으로 승격했습니다.

| 무엇 | 토큰 | 왜 램프에서 못 고르나 |
| --- | --- | --- |
| 학습 하단 콘솔 밴드·트레이 | `--asset-console-*` | SVG 에셋의 실제 면색과 이어 붙어야 함 |
| 우주 배경 그라데이션·별빛 | `--art-space-*` `--art-star*` | 배경 아트 (원칙1 예외) |
| 등급 칩 4색 | `--art-grade-*` | 별 아이콘 에셋과 세트 |
| 행성 링 그라데이션 | `--art-planet-*` | 행성 이미지와 세트 |
| 개념 학습 형광펜 | `--art-mark-*` | 형광펜 질감 |

이제 화면에는 hex가 한 곳도 없습니다. 색을 바꾸려면 `tokens.css`만 보면 됩니다.

## 브랜드 인상은 지켰습니다

색상(hue)은 건드리지 않고 명도만 조정했습니다. 홈 배경·오브젝트 이미지 247장이
지금 색조에 맞춰 **생성**돼 있고 같은 그림을 다시 뽑을 수 없기 때문입니다.

Figma 원색 중 흰 글자와 맞지 않는 값(자유모드 그린 `#58CC02`)은 탭에서 물러났지만,
글자가 얹히지 않는 장식용으로 `--brand-free-vivid`에 남겨 뒀습니다.

## 알아둘 것

**비활성 컨트롤은 대비 기준에서 제외됩니다.** 문제를 다 풀기 전 "제출하기" 버튼처럼
흐리게 보이는 것은 의도된 상태이고 WCAG도 예외로 둡니다.

**이미지 위 글자는 이 감사에 없습니다.** 배경이 사진·일러스트면 대비를 자동으로 잴 수
없기 때문입니다. 홈 화면 말풍선이 여기 해당합니다 — 눈으로 확인해야 합니다.

## 측정 방법

로컬 서버에 각 화면을 실제 테마 그대로 띄우고, 글자 요소의 계산된 색과 위로 올라가며
찾은 불투명 배경색으로 WCAG 공식을 적용했습니다.

화면마다 테마가 고정돼 있다는 점이 중요합니다 — 학습·과제·시험은 라이트,
nav·util은 다크로만 쓰입니다. 그래서 각 화면을 그 테마에서만 쟀습니다.
