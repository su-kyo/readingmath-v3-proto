# Phase 5 착수 지시서 — 디버그 패널 + 잔손질 12건

> 2026-08-19 사용자가 전 화면을 점검하고 낸 피드백 중, 판단이 끝나 실행만 남은 것들.
> 이 문서는 Phase 5 실행 세션(새 대화방)이 첫 메시지로 받는 지시서다.
> Phase 5가 끝나 옵시디언 기록까지 마치면 이 파일은 지워도 된다.

## 시작하기 전에

1. 프로젝트 `CLAUDE.md`와 `docs/design-system.md` §3.0b(칠면 3부류)를 먼저 읽는다.
2. 서버는 `.claude/launch.json`의 **rm-static**(8020)으로 띄운다. Bash로 띄우지 않는다.
3. 보고는 파일명 나열이 아니라 **화면 스크린샷**으로 한다. 다크·라이트 양쪽.
4. 사용자는 UI/UX 디자이너다. 코드를 읽지 않는다. 한국어로, 결론 먼저.

## 이 회차의 디자인 원칙 (사용자 피드백에서 추출 — 전 항목에 적용)

1. **대비는 한 번만.** 이미 대비를 준 요소를 테두리·박스로 또 감싸지 않는다.
2. **상태 표현이 정보를 가리면 안 된다.** 취소선처럼 내용을 읽기 어렵게 만드는 표현 금지.
3. **시스템 컬러(정답·오답·CTA)는 통통 튀게, 도메인 면(읽기·배경)은 차분하게.**
4. **다크모드에서 위에 뜨는 레이어가 더 밝다.**
5. **인터랙션 응답은 즉각.** 상태 전환 트랜지션은 짧게(대략 120ms 이내 감각).
6. **더미는 더미로 보이게.**
7. 색은 `styles/tokens.css` 변수로만. 팔레트 hex를 손으로 고치지 않는다.
8. 클래스명은 뜻이 읽히게 짓는다.

## 작업 목록 (순서대로)

### 0. 디버그 패널 — 가장 먼저 만든다

이후 모든 항목의 검수 도구가 되므로 맨 앞이다.

- **무엇**: 학습 화면(개념·유형·서술형·과제·시험)에서 상태를 강제 전환하는 작은 패널.
  - 현재 문제 정답 처리 / 오답 처리 / 전체 문제 한 번에 풀기(다음 버튼 활성화까지)
  - 결과 화면 계열: 시간 초과 상태 ↔ 제한 시간 내 상태 전환
- **어떻게**: 공통 스크립트 하나로. 주소에 `?debug=1`을 붙였을 때만 화면 구석에
  작게 나타나는 방식을 추천한다(배포본에서 일반 접근 시에는 안 보이게).
  화면마다 훅이 다를 수 있으니, 이번 회차 대상 화면들에 먼저 붙이고
  구조를 확장 가능하게 남긴다.
- **완료 기준**: 사용자가 문제를 직접 풀지 않고도 정답·오답·완료 상태 화면을
  버튼으로 오가며 볼 수 있다.

### 1. 끊어읽기 빈칸 — 정답 효과를 잠깐 보여주고 넘어가기 (피드백 1)

- **어디**: `concept/learn.html` (`scripts/learn-concept.js`)
- **무엇**: 빈칸 정답을 맞췄을 때 정답 효과(색 전환 등)를 짧게 유지한 뒤 다음으로
  진행한다. 지금은 효과를 볼 새 없이 넘어간다. 0.4~0.6초 감각.

### 2. '개념 요약하기' 모달 정리 (피드백 3)

- **어디**: `concept/organize.html`
- **무엇** 둘: ① 모달 안쪽의 박스-안-박스 제거 — 모달 프레임이 이미 면이므로
  내부 콘텐츠는 경계 없이 놓는다. ② 다크모드에서 dim 배경과 선지의 대비가
  거의 없다 — 모달·선지 표면을 dim보다 확실히 밝게 (원칙 4).

### 3. 더미 이미지 표기 통일 (피드백 4 · 공통)

- **무엇**: 선지 등에서 이미지 자리를 채우는 더미 div가 "예시 자리"임이 한눈에
  보이게 공통 스타일을 만든다 (예: 빗금 패턴 + "이미지 예시" 라벨).
  전 화면에서 같은 방식으로.

### 4. 이중 테두리 제거 (피드백 8 · 공통)

- **어디**: `concept/drill.html`의 주황 빈칸 바깥 연한 테두리가 확인된 사례.
  같은 패턴(강조 요소를 한 겹 더 감싸는 테두리·글로우)을 전 화면에서 찾아 제거.
- **주의**: CTA의 경계 장치 3종(450 면·딥 엣지·라이트 링)은 32배경 생존용
  설계라 제거 대상이 아니다 (`docs/design-system.md` 참고).

### 5. 오답 취소선 제거 (피드백 9)

- **어디**: `concept/drill.html` 스타일에 `line-through`가 있다. 다른 화면도 검색.
- **무엇**: 오답 확인 상태에서 오답 내용에 취소선을 긋지 않는다 — 오답도 읽어야
  할 정보다. 오답임은 색(오답 시스템 컬러)과 아이콘 등 내용을 가리지 않는
  방식으로 표현한다.

### 6. 개념 다지기 상단 문제 카드 — 정오 상태 대비 강화 (피드백 10)

- **어디**: `concept/drill.html` 상단 문제 카드 영역
- **무엇**: 정답·오답 상태가 배경과 경계가 흐릿하다. 상태색 vivid 토큰
  (`--ok-vivid`·`--no-vivid`)을 써서 또렷하게 만든다.
- **주의**: vivid 토큰의 **일괄 치환은 금지**다(다크 호버면에서 대비가 깨지는
  경계 케이스 있음 — 옵시디언 판단 기록 참조). 이 화면에서 눈으로 확인하며 적용하고,
  다른 화면으로 넓힐 때도 하나씩.

### 7. 주관식 키패드 — 물리 키보드 입력 지원 (피드백 11)

- **어디**: 키패드가 있는 화면 전부 (`concept/drill.html` · `concept/basic-ops.html` ·
  `concept/learn.html` · `essay/` 계열). 검색해서 전수 확인.
- **무엇**: 키패드 모달이 떠 있을 때 컴퓨터 키보드로 숫자·지우기(Backspace)·
  확인(Enter)이 동작한다. 화면 키패드와 같은 로직을 태워야 한다(따로 구현 금지).
- **중요 — 화면마다 붙이지 말고 공용 스크립트 하나로 만든다.** Phase 6에서 키패드를
  한 벌로 통일할 예정이라, 화면별로 흩어 놓으면 그때 전부 다시 정리하게 된다.
  키패드가 여러 벌이면 입력 처리만이라도 공용 모듈로 뽑아 각 화면이 그것을 부르게 한다.

### 8. 서술형 기본다지기 해설 — 흐름 통일 (피드백 16)

- **어디**: `essay/basics-v2.html`(현재 자유모드가 부르는 쪽) 해설 부분
- **무엇**: 해설이 세로 레이아웃에서 확정한 디자인과 다르고, 빈칸 맞추기 해설과
  순서 맞추기 해설이 한 번에 나온다. **푼 순서대로**(빈칸 해설 → 순서 해설)
  나오도록 흐름을 맞추고, 스타일도 세로 레이아웃 기준으로 통일한다.

### 9. 서술형 빈칸 선택 — 트랜지션 즉각화 (피드백 17)

- **어디**: 서술형 훈련의 빈칸 선택(주황 활성화) 트랜지션
- **무엇**: 선택 즉시 반응하는 감각으로 시간을 줄인다. 원칙 5.

### 10. index.html — 수학/과학 열 분리 + 서술형 확정안/킵안 정리 (피드백 15)

- **무엇** 둘:
  ① 화면 목록을 수학·과학 열로 나눈다 (콘텐츠 이원화 준비).
  ② 서술형의 **세로 레이아웃 안을 확정안**으로 본 목록에, **가로 안은 "킵"
  그룹**으로 분리해 표시한다. 어느 파일이 세로인지는 열어서 확인할 것
  (basics/drill의 v2 쌍 — 지금 자유모드는 v2를 부른다). **어느 파일도 지우지 않는다.**

### 11. 마무리

- 전 화면 404 검사(경로가 코드에서 조립되는 곳이 많아 문자열 검색만으로는 못 잡음).
- 색을 건드렸으면 `tools/cta-check.html`로 CTA 32배경 생존 확인.
- 커밋·푸시 (이 저장소는 시험용 — 커밋을 아끼지 않는다).
- 다크·라이트 스크린샷으로 항목별 보고.
- 사용자 확인 후, 옵시디언 `9 템플릿/작업 기록 지시문.md`를 읽고 작업 기록을 남긴다.
