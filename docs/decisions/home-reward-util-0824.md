## ⑤ 홈 보상 — 확정 사양 (7-4에서 결정)

- **미완료 = 홀로그램, 완료 = 실물.** 진행률에 따라 표현을 나누는 하이브리드는 폐기.
- **홀로그램은 흰색을 「칠하는」 것이 아니라 「빛을 더하는」 것**(`mix-blend-mode:screen`).
  결과가 배경 색을 먹어서 32배경 어디서나 어울린다 — **학기별 색 지정이 없다.**
  상태 구분은 색이 아니라 형태(흰 테두리 빛 + 스캔라인 + 글로우)가 맡는다.
- **밝은 배경 보완**: screen은 어두운 색이 무효라, 블렌드되지 않는 옅은 그늘을 뒤에 한 겹(`::after`).
- **스캔라인은 정지한 무늬**다. 대신 빛 한 줄이 7초에 한 번 훑는다.
  흐르는 빗금(3~8Hz)은 **눈 피로 때문에 금지** — 되살리지 말 것.
- **명판(단원명+진행)은 hover/탭 전용**, 위치는 **오브젝트 위쪽 고정**(정중앙·상자 아래 모두 폐기).
- **대표 캐릭터가 항상 최상위**(`.hero` z-index 30). 오브젝트도 명판도 캐릭터를 못 가린다.
- 검증: 32배경 실측으로 극단 7학기 선정 → 전부 통과. 성능은 `tools/holo-bench.html`에서
  **무대 7개에도 60FPS**(최적화 전 40.6FPS). 실제 홈은 무대 1개다.

**본화면 적용에서 정해진 것 (7-5)**

- **터치 판정** — 그림을 64×64로 줄여 「어디가 칠해져 있는지」 표를 만들어 두고,
  누른 자리가 비어 있으면 무시한다. 가장자리는 한 칸(약 1.6%) 넓혀 손가락에 너그럽게.
  마우스는 지나가면 뜨고, 손가락은 **탭했을 때만** 뜬다.
- **진행 세그먼트** — 한 칸 = 소단원 하나, 칸이 **3단계**(미진행 · 진행중 반칸 · 완료).
  「완료 소단원 수 / 전체」로 세면 소단원 1개짜리는 0%↔100%뿐이라 중간을 만들었다.
  집계 항목은 새로 만들지 않았다 — `nav/curriculum.html`이 이미 아는 값의 요약이다.
- **명판은 오브젝트 안이 아니라 별도 층에 있다.** 오브젝트끼리의 앞뒤는 절대 안 바뀐다 —
  명판을 오브젝트 안에 넣으면 그 오브젝트를 통째로 올려야 명판이 보이고, 그러면
  올린 오브젝트가 앞의 오브젝트를 뚫고 나온다. 층 순서는 오브젝트 < 명판(25) < 캐릭터(30).
- **명판은 완료 단원에도 뜬다.** 완료는 세그먼트 대신 「✓ 완료」로 적는다.
- **명판이 뜨는 동안 말풍선은 물러난다** — 중단 오브젝트의 명판 자리와 겹친다.
  캐릭터는 그대로 최상위.
- 남은 것: **태블릿 실기기 확인**, 성능 실측(`tools/holo-bench.html` ②번 항목).

## ④ 유틸 — 확정 사양 (7-6에서 결정 · 적용 완료)

**일러스트·그림 배경은 학습 계열 화면에서만 쓴다**(홈·학습·학기 네비게이션).
유틸에는 쓰지 않는다 — 1~2차 시안의 우주선 배경·베젤 방향은 폐기됐고 되살리지 않는다.

7-6에서 「토스풍 종이색 찾기」로 한 차례 더 헤맸다. **종이색을 바꾸는 문제가 아니었다.**
결론은 **흰 바탕 + 단일 램프**다.

**체계 세 줄** (`styles/util.css` 머리 주석과 같다)

1. **면은 뉴트럴-쿨 램프(n-000 / n-050 / n-100) 하나로만 쌓는다.**
   파랑은 「면」이 아니라 점·선·글자로만 쓴다. **초록·앰버는 쓰지 않는다.**
   화면이 얼룩져 보이던 원인이 이것이었다 — 쿨블루·초록(혜택 체크·할인)·
   앰버600(이벤트 카테고리, 사실상 갈색)·오렌지 네 hue가 섞여 있었다.
   옅은 면도 `n-050`·`blue-050` 두 종류라 같은 회색이 서로 다르게 보였다.
2. **「선택 = 반전 칠」이 단일 규칙.** 필터 알약·페이지네이션·과목 세그먼트·
   기간 타일·결제수단 타일이 전부 같다 — **다크는 밝은 면 + 먹색 글자,
   라이트는 먹색 면 + 흰 글자.** 라디오 동그라미를 쓰지 않는다.
3. **목록은 테두리 안에 담긴 시트, 선택지는 나란히 비교되는 타일.**
   떠 있는 블록과 그 사이 갭을 쓰지 않는다 — 호버 면이 위아래로 맞닿거나
   갭에 선이 떠 보인다. 시트 안에서는 호버가 꽉 찬 면으로 칠해지고
   라운드는 컨테이너가 잘라 준다.

난색은 CTA 하나(`--primary` 450 · 라벨 19px w800), 빨강은 오류에만. 그림자 없음.

**폭은 화면 성격별** — 목록·상세는 가운데 860px 좁은 칼럼, 결제만 2단(1160px).

**다크가 기본이다** (7-6 막바지에 「라이트 전용」에서 뒤집었다 — 서비스 전체가 다크
기본이라 학습 화면에서 유틸로 넘어올 때 화면이 튀었다). 라이트도 살아 있고,
학습 화면이 쓰는 `localStorage['rm-theme']`를 그대로 따라간다 — 저장된 값이
`'light'`일 때만 `<html data-theme="light">`가 붙는다. 각 화면 `<head>`의
부트스트랩 한 줄이 그 일을 하고, 먼저 실행돼 화면이 번쩍이지 않는다.
**유틸에는 테마 토글 버튼이 없다** — GNB 아이콘을 늘리는 일이라 넣지 않았다.
필요하면 별도로 결정할 것.

**결제 화면은 원본 구조를 버리고 다시 짰다.**

- ① 과목 → ② 이용 기간 → ③ 결제 방법 세 단계. **과목은 선택만**(가격 없음).
- 가격은 기간 타일에서 **월 환산가(22px, 비교축) + 총 결제금액(12.5px)**을 함께 적는다.
  월 단위가 부담이 덜해 비교에 좋지만, 실제 청구액을 놓치면 안 되기 때문이다.
- **실제 청구액은 오른쪽 요약의 히어로 숫자 하나(34px)로 못 박는다.**
  그 아래 `월 60,000원 × 6개월`이 근거로 붙고, 절약액은 `−70,000원`.
- 4개 요금제를 가로로 놓아 70,000 → 65,000 → 60,000 → 50,000이 한눈에 내려간다.

**설명 문장(캡션)을 두지 않는다.** 캡션을 달아야 한다는 건 구조가 말을 못 한다는 신호다.
단계 힌트·과목 설명·결제수단 설명·가상계좌 안내·안심 문구를 전부 지웠고,
남긴 문장은 **포함 항목 5줄(상품 내용)과 법적 고지 2줄**뿐이다.

**데이터는 하나도 빼지 않았다.** 「번호」만 화면에서 숨겼고(상세 이동 키로는 그대로 쓴다),
학습 기간·등록일·정가·판매가·할인율·일수·월 환산가는 전부 살아 있다.
공지 목록 **정렬을 등록일 최신순**으로 바꿨다 — 원본 데이터는 번호 순서와 날짜 순서가
어긋나 있어서, 번호를 빼면 뒤죽박죽으로 보인다.

**부가 상태는 주소로 연다** — `util/notice.html?state=loading|empty|error`
(월간보고서도 같다). 배포본에서는 쓰이지 않는다.
