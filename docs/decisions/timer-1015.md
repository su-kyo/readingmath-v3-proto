# 학습 타이머 — 진행 시간 / 제한 시간 (2026-10-15)

유형 · 서술형 머리줄 타이머가 진행 시간만 보여 줘서, 제한(60분)을 넘었는지 알 수 없었다.
「진행 시간 / 제한 시간」으로 바꾸고, 넘으면 빨강으로 표시한다. 견본은 스토리북 `styleguide/shells.html`의 「학습 헤더」다.

## 반영 범위

- 세는 화면 7장: `type/quiz` · `essay/basics` · `basics-v2` · `drill` · `drill-v2` · `advanced` · `report`
- 멈춘 화면 5장(`.is-paused`): `type/review` · `type/result` · `essay/drill-review` · `report-review` · `step-result`
- 결과 화면 3장의 「시간 초과 감점」 표시(`.chip--warn` → `.chip--over`): 앰버 → 빨강

## 판단

- **넘었을 때 표현은 「숫자 밝은 빨강 + 칩 2px 빨간 테두리」(B2).** 시안은 칩 전체 빨강(A) · 숫자만 빨강(B) · 테두리와 점(C) 셋이었다. 세션은 A를 추천했지만 사용자가 B를 고르고 테두리를 더했다.
- **넘은 뒤에도 계속 올라간다.** 초과분만 세는 「+02:10」 안은 시안 축에서 뺐다(사용자 결정).
- **결과 화면의 감점 표시도 빨강.** 같은 사건이 두 색(타이머 빨강 · 결과 앰버)이 되지 않게 했다(사용자 결정).

## 세션이 정한 것 (2026-10-15 사용자 확정)

- 제한 시간은 흰색 80% · 14px(진행 시간은 흰색 100% · 16px). 시안의 60%는 유형(틸) 칩에서 4.37이라 작은 글자 기준 4.5에 못 미쳐서 한 단계 올렸다. 결과는 틸 6.44 · 보라 9.07.
- 넘은 숫자 `--no-on-dark`(빨강 300): 틸 4.63 · 보라 6.84. 테두리는 `--no-solid`(500).
- 분은 60을 넘어도 분으로 센다(`62:10 / 60:00`, 두 시간이면 `120:00`). 제한 시간과 같은 단위로 읽히게.
- 해설 · 결과 화면(정지)도 「/ 60:00」을 붙이고, 넘은 채 멈췄으면 빨강을 남긴다.
- 서술형 해설 2장의 정지 이름이 `lheader__timer--pause`(모양 없음)여서 정지 표시가 안 붙었다. `.is-paused`로 맞춰 유형 해설처럼 흐림 + 일시정지 표시가 붙는다(화면이 바뀐다).
- 유형 해설의 정지 값(12:45)이 JS에 있던 것을 HTML로 옮겼다.
- 조사 문서 G11(타이머 칩 3종 n-900 · 검정 30%)은 어느 화면도 쓰지 않는 죽은 규칙이었다. 지웠다(`.cap-timer` · `.htimer` · `.qtimer`). 실제 칩은 이미 `--th-static-deep`.

## 개발자 전달 목록

1. **마크업.** `#hdrTimer > img + .lheader__time#timer + .lheader__limit`. 제한 시간 글자(`/ 60:00`)가 정본이다. JS가 이 글자를 읽어 넘었는지 판정한다.
2. **상태 셋.** 세는 중(기본) · `.is-over`(진행 > 제한, 같으면 아님) · `.is-paused`(해설 · 결과). 둘은 겹칠 수 있다.
3. **동작은 `scripts/learn-timer.js` 하나.** 화면마다 있던 1초 타이머 7벌을 걷어냈다. `RMTimer.set(초)` · `RMTimer.get()`. `?debug=1`이면 「제한 5초 전」 · 「시간 초과」 버튼이 붙는다.
4. **실서비스 값.** 제한 시간이 단계(유형 · 서술형)마다 다른지, 넘었을 때 감점 규칙(결과 화면 −10점)과 같은 기준인지 확인이 필요하다.

## 열린 것

- 결과 화면 데모 데이터가 어긋난다. 「시간 초과 감점」을 켜도 「소요」가 41:20(유형) · 28:10(개념)으로 제한보다 짧다. 서술형은 76:50.
- 개념 결과 JS가 없는 요소(`overLamp`)를 찾는다. 동작에는 영향이 없다.
- 개념 계열은 타이머가 없다(이번 범위 아님).
