## 이어받는 법 (새 대화방은 여기부터)

1. **이 문서를 끝까지 읽는다.** 진행 현황(아래) → 실측(§1) → 하지 않을 것(§2) →
   해당 단계의 「완료 기록」 순서로 보면 된다.
2. **저장소의 `CLAUDE.md`**를 읽는다(색 정책 v1.6 · 공용 부품 · 검수 도구).
3. 미리보기 서버 **rm-static(8020)**을 켠다. Bash 로 서버를 띄우지 않는다.
4. **공용 CSS·부품을 건드리기 전에 반드시 「전」을 찍어 둔다:**

   ```bash
   tools/screen-shot.sh /tmp/rm-before
   # ...수정...
   tools/screen-shot.sh /tmp/rm-after
   tools/screen-diff.py /tmp/rm-before /tmp/rm-after
   ```

   **부품을 옮겼는데 0.00% 가 나오면 성공이다.** 1% 넘게 바뀐 화면은
   `--crop 화면이름` 으로 잘라서 눈으로 확인한다.
   `nav/*` 의 0.1~2% 는 별이 반짝이는 잡음이라 회귀가 아니다.
   부품이 정말 같은지는 `tools/rule-compare.py <클래스>` 로 먼저 본다
   (`--count` 는 복붙/고유를 집계한다).

**이 회차에서 배운 함정 셋** — 같은 실수를 반복하지 말 것.

- **여러 줄 규칙을 한 줄만 지우면 CSS 가 통째로 깨진다.** 정규식으로 `.screen {`
  한 줄만 지웠다가 뒤따르는 `.wrap` 규칙까지 삼켜 과제 화면이 백지가 됐다.
  **중괄호 짝을 세서 규칙 단위로 지운다**(`rule-compare.py` 의 `rules_of()` 참고).
- **잘린 출력을 근거로 코드를 쓰지 않는다.** 비교 출력이 170자에서 잘렸는데 뒷부분을
  짐작해 옮겨 적어, 다섯 화면의 라벨 글자가 12→13px 로 커졌다. **원문 파일을 열어
  끝까지 읽고 그대로 복사한다.**
- **브라우저 캐시.** `?v=` 를 안 올리면 "고쳤는데 화면이 안 바뀐다"가 나온다.
  같은 날 여러 번 고칠 때는 날짜 뒤에 회차를 붙인다(`20260828-3`).
  **헤드리스 촬영은 캐시가 없어서 이 함정에 안 걸린다** — 그래서 더 헷갈린다.

## 2. 하지 않을 것

- **팔레트를 새로 뽑지 않는다.** 색 정책 v1.6(칠면 셋 · 450 스텝)은 그대로다.
  hex를 손으로 고치지 않는 규칙(CLAUDE.md ②-2)도 그대로다.

  `phase7-brief.md`에 있다. 스토리북에서 **「예외」로 명시**할 뿐이다.
- **화면 디자인을 바꾸지 않는다.** 2단계에서 1~2px이 움직이는 것 외에는
  보이는 결과가 달라지면 안 된다.
- **`essay/basics·drill`의 가로 안(킵)을 지우지 않는다.** 다만 **정리 대상에는
  포함한다** — 부품이 바뀌는데 이것만 안 따라오면 나중에 되살릴 수 없다.
- **빌드 도구를 도입하지 않는다.** 프레임워크 없는 순수 HTML이라는 성격을 유지한다.

| `.opt` | 7 | 116 | 72 | 44 | 두 가지 디자인 |
| `.chip` | 5 | 32 | 18 | 14 | 섞여 있음 |
| `.card` | 8 | 31 | 10 | 21 | **대부분 다른 물건** |
| `.qtab` | 5 | 23 | 8 | 15 | **대부분 다른 물건** |

**셸 계열은 진짜 복붙이었다** — 콘솔바·도구버튼·배경·게이지·토스트·패널.
전부 끌어올렸고 대부분 화소 단위로 동일하게 옮겨졌다.
**본문 계열은 아니다.** `.opt`(선택지)는 과제(1.5px 테두리·좁은 여백)와
유형(60px 높이·다른 상태 표현)이 실제로 다른 디자인이고, `.card`·`.qtab`은
이름만 같다. 합치면 디자인이 바뀐다 — §2가 금지한 일이다.

**`.seg` 는 다섯 화면이 서로 다른 것에 쓰고 있다** — 끊어읽기 구간(개념 학습),
LED 띠(결과), 분절 토글(과제 풀이·자유모드), 라벨(시험 풀이).

**그래서 남은 일은 「합치기」가 아니라 「이름 가르기」다.**
`.opt` → `.opt`(과제) / `.qopt`(유형), `.seg` → 넷으로, 토스트 다섯 이름 → 하나.
이건 **CSS만이 아니라 마크업과 JS를 함께 고치는 일**이라 별도 회차로 잡는 게 맞다.

**끝나는 지점을 고쳐 잡는다.** 「인라인 1,200줄」은 남은 것이 전부 복붙이라는
전제에서 나온 숫자였고, 그 전제가 틀렸다. **현실적인 목표는 인라인 3,500줄 안쪽**
(순수 복붙 `.blank` 처리 + 이름 가르기 이후)이다. 남은 인라인의 상당 부분은
**그 화면에만 있는 진짜 화면 스타일**이고, 그건 있어야 할 자리에 있는 것이다.

#### 이번에 한 실수 하나 더 — 잘린 출력을 근거로 코드를 썼다

비교 스크립트가 규칙을 170자에서 잘라 찍었는데, **그 뒷부분을 읽지 않고 짐작해서**
공용 CSS에 옮겨 적었다(라벨 글자 12→13px · 자간 부호 반대). 다섯 화면의 라벨이
한꺼번에 커졌고, 전후 화소 대조에서 1~2.7% 차이로 드러나 원문을 다시 읽고 고쳤다.
**부품을 옮길 때는 원문을 끝까지 읽고 그대로 복사한다. 요약된 출력을 믿지 않는다.**
(화소 대조가 없었으면 못 잡았다 — 이 검증 방식을 계속 쓸 것.)

### 4-4. 세미 스토리북 (2일) — **사용자 결정: 배포에 포함**

진짜 Storybook(React용 도구)은 쓰지 않는다. **경험만 같게** 만들고 순수 HTML로 연다.

**구조** — `styleguide/` 폴더를 만들고 네 장으로 나눈다.
지금 `styleguide.html`은 35KB로 이미 한계다. **지우지 않고**
`styleguide/foundations.html`로 옮겨 살린다 — 색·타이포 부분은 이미 최신이다.

```
styleguide/foundations.html   색 · 타이포 눈금 · 간격/모서리/층
styleguide/components.html    버튼 · 배지 · 칩 · 문제 블록 · 게이지 · 문항 탭 · 토스트
styleguide/shells.html        콘솔바 · 학습 헤더 · 보조 모니터 · 키패드 · 연습장 · GNB/서랍
styleguide/patterns.html      화면 껍데기 · 목록 상태(로딩/빈/실패) · 유틸 예외 체계
```

왼쪽 목록은 **공용 부품 하나로 만들어 네 장이 공유한다.** 네 벌로 복사하면
이 문서가 진단한 문제를 스토리북이 그대로 반복하게 된다.

**지킬 것 넷**

1. **부품마다 상태를 전부 세운다.** 기본만 놓지 않는다 — 호버·눌림·비활성·선택,
   그리고 **빈 값 · 긴 이름 · 0건 · 많은 개수**까지. 시안에서 잘 빠지는 자리다.
2. **라이트/다크를 한 화면에 나란히.** 토글로 왔다갔다 하면 어긋난 면을 못 본다.
3. **쓰는 화면 목록을 부품 옆에 적는다.** 「이걸 고치면 어디가 영향받나」가 없으면
   유지보수가 안 된다. 이 숫자는 5단계 스크립트가 자동으로 센다.
4. **JS가 넣는 변수 목록**(§1-5)을 patterns에 싣는다.

`index.html`에서 스토리북으로 가는 링크를 추가한다(CLAUDE.md ④).
`.vercelignore`에서 `styleguide/`를 **제외하지 않는다** — 배포 포함이다.

**「쓰는 화면 수」는 `tools/usage-scan.py` 가 센다.** 36화면 마크업을 훑어

상태는 기본만 놓지 않았다 — 호버·눌림·비활성·선택에 더해 **0% · 100% · 빈 값 ·
긴 라벨 · 많은 개수**를 함께 세웠다.

**옛 `styleguide.html` 은 지웠다.** 색·타이포는 foundations 로 옮겨 다시 썼고 나머지 절은
components·shells 가 덮는다. 둘을 남기면 어느 게 현행인지 알 수 없게 된다
(되살리려면 `c32d0f2` 의 부모에서 그 파일만 꺼내면 된다).

**문서를 만들다 드러난 것 셋** — 코드만 봐서는 안 보이던 것들이다.

1. **콘솔바에서 토큰이 아닌 곳은 좌우 일러스트뿐이다.** 면색은 `data-section` 이 정하는데
   그림은 화면 마크업의 `<img src>` 가 고르고, **이름의 좌우도 뒤바뀌어 있다**(왼쪽 자리에
   `-right`). 계열을 늘릴 때 이 8개 파일과 화면 마크업을 함께 챙겨야 한다.
2. **900px 아래에서 그 일러스트가 사라지고** 립이 22px 라운드를 얻는다. 680px에서 경로
   중간 조각, 520px에서 도구 버튼 글자가 빠진다. 어디에도 안 적혀 있던 규칙이라 실었다.
3. **라이트에서 배지·유형칩의 대비가 다크보다 눈에 띄게 약하다.** 나란히 세우니 바로 보였다 —
   토글로 오갔으면 못 봤을 종류다. **⑤로 넘긴다.**

**만들며 잡은 함정 넷** (다음 회차에 같은 데서 걸리지 말 것)

- `base.css` 의 `html,body{height:100%}` 때문에 **액자 높이가 늘 150px 로 굳었다.**
  액자 안에서만 `height:auto` 로 되돌리고 `ResizeObserver` 로 따라가게 했다.
- **`:root[data-section]` 은 `<html>` 에만 걸린다.** 가짜 `div` 에 붙여 재면 일곱 계열이
  전부 같은 색으로 찍힌다. `<html>` 의 값을 잠깐 갈아끼우고 읽은 뒤 되돌린다.
  같은 이유로 **한 액자 안에서 계열을 섞을 수 없다** — 계열은 화면 단위 값이다.
- **`mix-blend-mode:difference` 라벨**은 중간 밝기 칩에서 보색이 튀어 오히려 안 읽힌다
  (파랑 칩에 주황 글자). 칩 밝기를 재서 검정/흰색을 고르게 바꿨다.
- 토큰의 `url("../assets/…")` 는 **따옴표와 상대경로 둘 다** 손봐야 `style` 속성에 들어간다.

**검증** — 40화면 링크 검사 깨진 링크 0(남은 것은 JS 조립 경로 false positive),
4장 콘솔 오류 0, 좌측 목록·배지·화면 수 자동 표시 확인, 네 장 전체를 헤드리스로 찍어 눈으로 확인.

### 4-5. 재발 방지 장치 (반나절)

이번 정리는 한 번으로 끝나지 않는다. **사람이 지키는 규칙을 기계가 지키는 규칙으로**
옮긴다.

1. **`tools/style-audit.py`** — §1의 실측을 스크립트로 만든다. 출력은
   토큰 밖 색 / 원시 px / 눈금 이탈 / 중복 정의 / 미사용 토큰 / 부품별 사용 화면 수.
   §1의 표와 같은 모양으로 찍어서 **다음 회차에 바로 비교**할 수 있게 한다.
2. **`?v=` 번호를 날짜 하나로 통일한다.** 파일별로 세지 않는다 — 세는 순간 또 어긋난다.
   전 화면이 같은 값(예: `?v=20260830`)을 쓰고, 뭐든 고치면 그날 날짜로 한 번에 바꾼다.
   번호 없는 링크 7개도 이때 붙인다.
3. **테마 부트스트랩 복붙 15화면**을 한 벌로 합칠 수 있는지 본다.
   (유틸 화면의 `localStorage['rm-theme']` 읽기 로직 — 인라인이어야 깜빡임이 없으므로
   **합치지 못할 수도 있다.** 못 합치면 그 이유를 문서에 적는다.)
4. **커밋 전 검사에 스타일 검사를 붙일지는 선택.** 붙이면 확실하지만 커밋이 느려진다.
   판단해서 사용자에게 물어본다.
5. **④에서 넘어온 것** — 라이트 모드에서 배지·유형칩·난이도 블록의 대비가 다크보다
   눈에 띄게 약하다(틴트가 흰 배경에 묻힌다). 스토리북에서 나란히 세우니 드러났다.
   색 정책 v1.6의 「텍스트 칠면 4.5」 잣대로 라이트 쪽 틴트/잉크를 다시 본다.
6. **`docs/README.md` · `CLAUDE.md` · `README.md`를 이때 한 번에 맞춘다.**
   design-system.md는 8/17에 멈춰 있어 Phase 7 유틸 체계, Phase 8 학습 기록,
   보조 모니터·키패드·연습장·서랍·행성 홈이 통째로 빠져 있다.

## 7. 세션이 임의로 정한 것 (다르게 보면 말할 것)

- SVG 일러스트 색은 검사 제외. 단 **좌표 그래프는 포함**(그림이 아니라 데이터 UI).
- 마스크용 `#000/#fff`는 **색이 아니라 도형 도구**로 보고 제외.
- 주석 안의 참고 hex도 제외.
- §1의 진단 순서를 심각도가 아니라 **고치는 순서**로 놓았다.
- `essay/basics·drill` 가로 안(킵)은 지우지 않되 **정리 대상에 포함**.
- `figma-palette/` · `video/` · `tools/`는 실측에서 제외.
